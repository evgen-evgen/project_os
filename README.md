# Project OS

Минимальный локальный планировщик проектов: одностраничный интерфейс плюс крошечный Node-сервер для сохранения данных на диск и выгрузки в Markdown.

## Зачем

Project OS нужен, чтобы видеть:

- какие проекты сейчас активны;
- какой прогресс по каждому проекту;
- какие milestones и задачи уже выполнены;
- какая задача является следующей (`NEXT`);
- какие идеи лежат в Inbox;
- какие проекты отложены в Backlog или Paused.

Главная идея: у каждого активного проекта должна быть одна понятная следующая задача.

## Запуск

Вариант 1 — просто в браузере: открыть `main.html`, работает локально без сервера и без интернета, данные в `localStorage`.

Вариант 2 — в Docker (данные сохраняются на диск в `./data`, генерируется Markdown для Obsidian):

```bash
docker compose up -d --build
# открыть http://localhost:8090
```

Один и тот же файл `main.html` работает в обоих режимах: при запуске он пробует загрузить состояние с `/api/state`, а при сохранении пишет и в `localStorage`, и на сервер.

## Возможности

- создание и редактирование проектов;
- статусы: `Active`, `Backlog`, `Paused`, `Done`;
- milestones внутри проекта;
- задачи внутри milestone;
- описание (заметка) для каждой задачи — кнопка ✎ или двойной клик по названию;
- отметка выполненных задач;
- одна `NEXT`-задача на проект;
- автоматический расчёт прогресса;
- общий блок следующих действий;
- быстрый Inbox для идей;
- экспорт данных в JSON;
- импорт данных из JSON;
- автоматическая выгрузка проектов и Inbox в Markdown-файлы (читается через Obsidian).

## Хранение данных

При запуске через Docker данные сохраняются на сервере:

- `data/state.json` — полное состояние (проекты, inbox);
- `data/*.md` — Markdown-файлы, по одному на проект + `Inbox.md`, генерируются автоматически при каждом сохранении.

Папку `data/` можно открыть как vault в Obsidian и смотреть проекты оттуда. Формат MD: frontmatter (`title`, `status`, `progress`, `next`), задачи — чекбоксы, NEXT-задача помечена тегом `#next`, описание задачи — с отступом под ней.

Если открыть `main.html` локально без сервера — данные остаются в `localStorage` браузера (для резервной копии используй `Export`). При работе через Docker с нескольких браузеров одновременно действует правило «последнее сохранение побеждает».

## Структура

```text
main.html           — приложение (HTML + CSS + JS в одном файле)
server.js           — минимальный Node-сервер (без зависимостей): раздача + /api/state + генерация Markdown
Dockerfile          — образ node:22-alpine
docker-compose.yml  — запуск, порт 8090 на хосте, данные в ./data
data/               — state.json + Markdown-файлы (создаётся автоматически)
```

Внешние библиотеки и база данных не используются.

## Логика

```text
Project
 └── Milestone
      └── Task
```

Пример:

```text
CEO Agent
 └── MVP
      ├── ✓ Database
      ├── ✓ PLAUD integration
      ├── → Email integration   NEXT (описание: какой API использовать, где ключи)
      └── ○ Cloud deployment
```

## Правило фокуса

Желательно держать одновременно не больше 3–5 активных проектов.

У каждого активного проекта стоит определить одну задачу `NEXT`.

Так главный экран превращается не просто в список дел, а в ответ на вопрос:

> Что мне делать дальше по каждому проекту?
